# Quantum ESPRESSO acquisition and execution record

The published Fe wavefunctions were generated by QE 7.3.1. The separate
recalculation proposed here uses QE 7.5 and must pass the eight-point energy and
C4 comparison before its path is associated with the earlier endpoint finding.
Even agreement does not establish identity with the missing original SCF
potential. Original Phase 9 files are read only.

## Portable build

- Distributor: [QMatSuite Windows QE](https://github.com/QMatSuite/quantum-espresso-windows-exe).
- Pinned release: [qe-7.5-win-oneapi-msmpi](https://github.com/QMatSuite/quantum-espresso-windows-exe/releases/tag/qe-7.5-win-oneapi-msmpi).
- Upstream build tag named by the release: `qe-7.5-win-oneapi-msmpi-20251223-d409e9b`.
- Asset: `qe-7.5-win-oneapi-msmpi.zip`, displayed size 382 MB.
- Published SHA256: `e50ec7368a5b7a964eb5084e0a13464ba2628d4e147c16227e876002ea34fdf7`.
- Release assets and digest: [expanded asset listing](https://github.com/QMatSuite/quantum-espresso-windows-exe/releases/expanded_assets/qe-7.5-win-oneapi-msmpi).
- The distributor states that binaries and runtime DLLs are colocated and that
  the distribution includes runtime licenses. It identifies QE as GPL v2 or
  later. These are distributor statements; a publisher digest check is not an
  independent audit of the compiler or every bundled binary.

The script `acquire_qe.py` downloads only this pinned asset, checks SHA256,
rejects archive path traversal and links, and extracts only below `fe/software`.
It does not run an installer or change the registry, global PATH, WSL, or system
software. Acquisition completion is evidenced by `software/ACQUISITION.json`,
not by this planning document. Execution is evidenced separately by each
experiment's `RUN.json` and original `pw.out`/`pw.err`.

The [official QE installation guide](https://www.quantum-espresso.org/Doc/user_guide/node16.html)
recommends WSL2 as its safest Windows route and also discusses native compilation.
No WSL installation or compiler toolchain change was performed here.

## Local inventory and access attempts

On 2026-11-02, PATH, miniconda `Library/bin` and `Scripts`, and first-level
matching Program Files directories did not contain an existing QE or Wannier
executable. `wsl.exe` returned installation help and no Lxss distribution entry
was found. This is a bounded inventory, not a claim to have searched every disk.

The first Python GitHub API request was blocked by the ordinary execution
network boundary. The authorized external-network retry reached GitHub but was
rate limited (HTTP 403). The public release page and asset digest were therefore
verified through web access, and the pinned release asset was requested directly.
Any incomplete `.partial` archive remains available for diagnosis and is never
silently treated as a usable installation.

The complete distribution is relatively large and download progress must be
distinguished from a finished installation. Neither a prepared input nor an
archive download constitutes new DFT evidence.
